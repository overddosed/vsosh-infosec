Теперь нужно поискать вектор атаки, запустим команду для поиска файлов с установленным `SUID-битом`.
`SUID - Set User ID`, это специальный тип прав доступа в `Linux/Unix`, который позволяет пользователю запускать файл с правами владельца этого файла, а не с правами того, кто его запустил.
```bash
find / -perm -4000 2>/dev/null

# find / - искать по всей системе, начиная с /
# -perm -4000 - искать файлы, у которых установлен бит с числовым значением 4 в четвертом разряде (это и есть SUID)
# 2>/dev/null - отбросить все сообщения об ошибках (например когда у текущего пользователя нет прав просматривать какие-то папки), чтобы они не засоряли вывод
```
Эта команда ищет программы, которые при запуске обычным пользователем выполняются с правами владельца этого файла.
![[Pasted image 20260511093328.png]]
Видим в списке `/usr/bin/sed`
Утилита `sed` предназначена для потокового редактирования текста. Поскольку на ней стоит `SUID-бит`, она может читать любые файлы в системе, к которым есть доступ у владельца файла `sed` (в данном случае - доступ на чтение любого файла)
Если администратор по ошибке поставит `SUID-бит` на "опасную" утилиту, которая умеет читать файлы, выполнять команды или редактировать текст (как `sed`, `vim`, `find`, `bash`), то любой пользователь в системе может читать файлы от `root`.

```payload
sed "" .flag
```

Утилита `sed` (`Stream Editor`) предназначена для преобразования текста. Её стандартное поведение - читать файл построчно, выполнять над строкой команду (если она есть) и выводить результат в терминал (`stdout`).

Когда мы пишем `sed "" .flag`, то передаем пустую команду в кавычках.
`sed` видит, что команд для изменения текста нет, поэтому он просто берет каждую строку файла и, ничего с ней не делая, «выплевывает» её обратно в терминал.
По сути, в таком виде `sed` превращается в обычную команду `cat`.
